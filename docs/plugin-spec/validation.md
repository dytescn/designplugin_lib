# 字段与安装校验规范

本文统一规定 `dytes.json`、包内容文件与 FFI 写入接口的字段限制和错误行为。
目标是：**已知字段严格校验，非法输入直接报错，不用空值、空数组或默认值代替错误。**

> 本文是规范草案，代码尚未按此逐项实现。各字段的“当前实现”见对应 issue。

## 1. 基本原则

- **已知字段必须严格校验**：类型、枚举、格式、长度、归属和唯一性不符合要求时返回错误。
- **不得静默降级**：结构错误不能当作空数组、空对象、空字符串或“没有内容”。
- **区分三种状态**：
  - 文件不存在：保留原数据；
  - 文件存在且显式为空（如 `[]`、`{ "tools": [] }`）：表示清空；
  - 文件存在但结构错误：返回错误。
- **先校验后写入**：安装/更新应在写主表、designdb、kv 之前完成字段校验，避免部分安装。
- **错误可定位**：错误消息带文件、下标和字段名，例如 `taskflows[2].uid 必须是非空字符串`。
- **未知扩展字段**：默认允许但忽略，不得依赖；如果产品要求完全拒绝未知字段，
  需要单独定义严格模式，避免破坏前向兼容。

## 2. 错误码约定

| 场景 | 错误码 |
| --- | --- |
| 字段缺失、类型错误、格式错误、超长、枚举非法 | `400103` |
| 唯一键冲突、跨插件归属冲突 | `400409` |
| 文件 / 目录读取失败 | `500300` |
| 引用的插件不存在 | `400404` |

## 3. `dytes.json` 字段

| 字段 | 严格规则 | 失败 |
| --- | --- | --- |
| `uuid` | 必填；非空；RFC 4122 UUID 格式（推荐 v4）；全局唯一 | `400103` / `400409` |
| `name` | 必填；`[a-z0-9_-]+`；建议 1–128 字符；与库文件名匹配 | `400103` |
| `version` | 必填；`MAJOR.MINOR.PATCH`；不得用数字类型；发布递增 | `400103` |
| `description` | 可选；字符串；建议 ≤ 500 字符 | `400103` |
| `type` | 可选；Dytes 包类型（`plugins` / `sys`）；不等于 `plugins_type` | `400103` |
| `plugins_type` | 可选；为空表示不同步 kv；非空必须命中已知映射或 `design_*` 前缀 | `400103` |
| `target` | 可选；默认 `common`；非空；建议 `[a-z0-9_-]+` | `400103` |
| `use_ai` | 归一化为 `0/1`；只有 `1`、`true`、`yes`、`on` 为开启，其他为 `0` | — |
| `platform-exports` | 可选；对象；键只能是 `windows` / `linux` / `macos`；值必须是对象；声明的目标文件必须在包内存在且为文件 | `400103` / `500300` |
| 未知字段 | 允许但忽略，不得依赖 | — |

`plugins_type` 的严格范围：

- 已知：`chat_think`、`chat_reply`、`chat_plugins`、`sys_plugins`、`plugins`、`plugins_coreldraw`；
- `design_*`：必须匹配 `design_[a-z0-9_]+`；
- 空字符串：允许，表示不同步 kv；
- 其他值：严格模式返回 `400103`，不再静默按“不同步”处理。

### 3.1 `design_*` 包

`plugins_type` 以 `design_` 开头的包还必须满足
[package-types.md](./package-types.md)：

- **必须**提供 `mcp.json`，`tools` 必须是数组；
- `use_ai` 归一化为 `1` 时**必须**提供至少一个有效 `skills/*.md`；
- 其余字段按本文 §3、§4、§7 校验。

`platform-exports` 还要求：

- 源路径必须是包内相对路径，不得是绝对路径或通过 `..` 越出包根；
- 目标文件名不得包含路径分隔符；
- 扩展名必须与平台匹配（`.dll` / `.so` / `.dylib`）；
- 当前平台没有可用库文件时返回 `500300`。

## 4. `skills/*.md`

| 项目 | 严格规则 | 失败 |
| --- | --- | --- |
| 目录 | 必须直接位于包根，只读取一层 `*.md` | `500300` |
| 文件 id | 文件名去 `.md` 后匹配 `[a-z0-9_-]+`，建议 ≤ 128 字符 | `400103` |
| 全局唯一 | `_id` 在所有插件范围内唯一；与已有其他插件冲突时报错 | `400409` |
| `content` | 非空；UTF-8 字节数 ≤ 1 MiB（1,048,576） | `400103` |
| `name` | 来自首个 `# ` 标题；非空；≤ 120 字符 | `400103` |
| `description` | 可选；≤ 500 字符 | `400103` |
| 控制字符 | 不允许 NUL 和除 `\n` `\r` `\t` 外的控制字符 | `400103` |
| 模板占位符 | 不允许 `{{base_system_prompt}}`、`{{categories}}`、`{{skills}}`、`{{rules}}` | `400103` |
| 空文件 | 跳过，不生成技能；升级时可能导致旧技能被 prune | — |

## 5. `prompts.json`

| 项目 | 严格规则 | 失败 |
| --- | --- | --- |
| 顶层 | 数组，或 `{ "prompts": [...] }`；`prompts` 必须是数组 | `400103` |
| 文件不存在 | 保留原提示词 | — |
| 显式空 | `[]` 或 `{ "prompts": [] }` 表示清空 | — |
| 元素 | 每个元素必须是对象 | `400103` |
| 标识 | 至少一个 `id` 或 `name`；`id` 建议 `[a-z0-9_-]+`、≤ 128 字符；`name` 非空 | `400103` |
| 内容 | `content` 非空；去首尾空白后 UTF-8 字节数 ≤ 150（对应 50 个汉字） | `400103` |
| 重复键 | 同一包内 `id` / `name` 的合并键不得重复 | `400409` |
| 字段类型 | `category` 为字符串；`sort` 为整数；`is_enabled` 归一化为 `0/1` | `400103` |
| 控制字符 / 模板占位符 / 密钥 / 用户数据 | 不得包含 | `400103` |

不得把 `{ "prompts": null }`、`{ "prompts": {} }`、`{}` 当作空数组；要清空必须显式写空数组。

## 6. `taskflow.json`

| 项目 | 严格规则 | 失败 |
| --- | --- | --- |
| 顶层 | 数组，或 `{ "taskflows": [...] }`；`taskflows` 必须是数组 | `400103` |
| 文件不存在 | 保留原任务流 | — |
| 显式空 | `[]` 或 `{ "taskflows": [] }` 表示清空当前插件元素 | — |
| 元素 | 每个元素必须是对象 | `400103` |
| 合并键 | 必须有非空 `uid` 或 `name`；`uid` 建议 `[a-z0-9_-]+`、≤ 128 字符 | `400103` |
| 重复键 | 同一包内合并键不得重复（`uid` 与另一个元素的 `name` 相同也算重复） | `400409` |
| `plugin_uuid` | 如果提供必须是非空字符串，且等于当前插件 UUID | `400103` / `400409` |
| 跨插件冲突 | 合并键命中其他插件的元素时返回冲突，不得覆盖 | `400409` |
| 无 key 元素 | 不得直接追加；必须报错 | `400103` |

空数组是显式清空；结构错误、缺少 key、重复 key、跨插件覆盖都不是“空内容”。

## 7. `mcp.json`

| 项目 | 严格规则 | 失败 |
| --- | --- | --- |
| 查找 | 包根 `mcp.json` 优先，其次 `mcp/mcp.json` | — |
| 文件不存在 | `chat_*` 允许并保留原能力；`design_*` 发布时必须提供 | — |
| 顶层 | 必须是对象；`tools` 必须是数组 | `400103` |
| 显式空 | `{ "tools": [] }` 表示清空该插件能力 | — |
| tool | 每个 tool 必须是对象 | `400103` |
| `name` | 必须非空；建议 `[a-z0-9_-]+`、≤ 128 字符；同一包内不得重复 | `400103` / `400409` |
| `title` / `description` | 必须非空；建议 ≤ 500 字符 | `400103` |
| `uuid` / `id` | 建议显式提供；格式 `UUID` 或 `{plugin_uuid}:{name}`；全局唯一 | `400409` |
| `ffi_symbol` | 可选；如果提供必须非空 | `400103` |
| schema | `inputSchema` / `outputSchema` 如果提供必须是 JSON 对象 | `400103` |
| `use_ai` | 归一化为 `0/1` | — |

缺少 `tools`、`tools` 为 `null`/对象/字符串、tool 不是对象都属于结构错误，不能按空能力清理。

## 8. FFI 写入路径

FFI 直接写入和包安装使用同一套字段规则：

- `post_plugins` / `update_plugins` / `patch_plugins`：`uuid`、`name`、`version`、
  `plugins_type`、`target`、`platform` 按 §3 校验；`enabled` / `public` 只接受 `0/1`。
- `post_skills` / `update_skills` / `patch_skills`：`id`、`name`、`category`、`content`、
  `description`、`params_schema` 按 §4 校验；`plugin_uuid` 必须指向已安装插件。
- `post_function` / `update_function` / `patch_function`：`plugin_uuid`、`name`、
  `title`、`description`、`ffi_symbol`、schema、`use_ai` 按 §7 校验；
  能力 `uuid` 冲突时不得静默接管其他插件。
- `update_prompts`：按 §5 校验，包括 150 字节上限。
- `update_taskflow`：按 §6 校验，但它是全局整体覆盖，单插件增量仍应使用安装/更新流程。
