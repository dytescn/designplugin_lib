# 安全规范

本文规定插件在文件、权限、内容、隐私与供应链方面的安全要求。
涉及安全条款时，**必须**优先满足本文，再考虑功能便利。

## 1. 路径与文件

- `install_plugin` / `update_plugin` 的 `dir` **必须**指向插件的最终安装目录，
  推荐 `./plugins/<name>/`；**不得**指向系统目录、用户主目录、数据库目录或其他插件目录。
- 调用方**必须**校验 `dir` 不通过 `..` 越出允许的插件根目录；**不得**直接透传外部输入。
- 包内**不得**包含：
  - SQLite 数据库、日志、缓存；
  - API Key、访问令牌、私钥、证书、`.env`；
  - 用户数据、聊天记录、带个人信息的截图；
  - 指向开发者本机的绝对路径。
- 动态库**必须**来自可复现的 release 构建；**不应**随包发布 PDB、调试符号或中间产物。
- 安装流程不会复制文件；包所在目录**必须**就是运行时目录，**不得**依赖安装后再搬运。

## 2. 输入与内容安全

- 技能 `content` 与提示词 `content` **不得**包含控制字符（`\n`、`\r`、`\t` 除外）；
- **不得**包含以下模板占位符，否则 FFI 更新会被拒绝：
  `{{base_system_prompt}}`、`{{categories}}`、`{{skills}}`、`{{rules}}`；
- 提示词**不得**包含越权指令，包括但不限于：
  - 要求忽略系统提示或开发者指令；
  - 要求泄露系统提示、密钥、令牌或内部配置；
  - 要求绕过权限、审批或安全策略；
  - 要求执行任意命令、访问任意路径或上传本地文件。
- 技能正文**应当**声明适用边界与失败处理，**不应**假设调用方会做额外校验；
- 用户输入**不得**直接拼接进系统提示；需要拼接时**必须**使用明确的模板占位与转义策略；
- 示例中的命令**不得**包含 `rm -rf`、格式化磁盘、修改系统配置等危险操作。

## 3. 权限与开关

| 字段 | 要求 |
| --- | --- |
| `mask` | **必须**遵循最小权限；默认 `0`；提权需在发布说明中说明理由 |
| `use_ai` | **必须**明确是否参与 AI 召回；涉及隐私数据时**不应**开启 |
| `is_system` | **必须**仅由内置插件使用；公共插件**不得**设为 `1` |
| `is_enabled` | 默认 `1`；**不得**默认开启高风险能力 |
| `public` | **必须**按实际发布范围设置；内部插件**不得**标记为公开 |

- 能力的 `use_ai` **应当**与插件 `use_ai` 保持一致；单独开启时**必须**说明原因；
- **不得**通过 `patch_plugins` 绕过发布流程修改 `mask` 或 `status`；
- 公共插件**不得**默认启用文件写入、命令执行、网络上传等高危能力。

## 4. 隐私与数据

- 提示词、任务流、能力 schema / example 中**不得**包含真实用户数据；
- kv 同步只写入提示词的 `content` 与必要元数据；**不得**把用户会话、文件内容写入 kv；
- 日志与错误信息**不得**回显密钥、令牌、完整用户输入或本机绝对路径；
- 示例数据**必须**使用虚构值，UUID、名称、地址**不得**对应真实用户或生产环境；
- 删除插件时**必须**按 [data-model.md](../data-model.md#53-清理范围) 确认清理范围：
  `delete_plugins` 不会自动删除技能、提示词、任务流，需另行处理。

## 5. 依赖与供应链

- 动态库的版本**必须**与 `dytes.json.version` 一致；
- 依赖的 sys 包（如 `database`、`designdb`、`kv_lib`）**必须**在清单中声明版本范围；
- 发布包**必须**通过 `dytes` 的 checksums 校验；**不得**手工覆盖已发布文件；
- **不得**在安装后从网络下载并执行未校验的代码或库；
- 第三方库**必须**来自可信来源，并在发布说明中列出新增依赖；
- 发现 checksum 不一致时，**必须**重新生成并发布新 patch 版本，
  **不得**直接覆盖已有版本路径（参考 `issues/checksums-mismatch.md`）。

## 6. 安全评审触发条件

出现以下任一变更时，**必须**进行安全评审后再发布：

- 新增或修改 `ffi_symbol`、能力 schema、文件 / 网络 / 命令执行行为；
- 修改 `mask`、`public`、`is_system`、`use_ai` 的默认值；
- 新增提示词或技能，且会读取用户文件、剪贴板、网络或系统信息；
- 引入新的第三方动态库或运行时依赖；
- 修改 kv 同步范围或写入内容；
- 处理个人信息、企业数据或受监管数据。

## 7. 安全事件处理

- 发现越权、注入、数据泄露或供应链问题时，**必须**立即停止发布；
- 评估影响范围（插件版本、能力、kv 记录、用户数据）；
- 发布修复版本，并在发布说明中写明受影响版本与升级方式；
- 需要回滚时，**不得**覆盖旧版本文件，应发布新的修复版本。
