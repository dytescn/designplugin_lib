# [P1] 提示词 kv 同步：空数组不清理旧记录，类型切换会遗留旧集合

- 发现日期：2026-11-11
- 代码版本：`plugin_lib` 1.0.20
- 位置：
  - `src/utils/package.rs` `sync_prompts` / `sync_prompts_without_file` / `sync_prompts_kv`
  - `src/utils/kv.rs` `list_records` / `collection_exists`
- 状态：已处理（2026-11-11）

## 现象

1. `sync_prompts_kv` 在 `records.is_empty()` 时直接返回：

   ```rust
   let records: Vec<(String, String)> = prompts.iter().filter_map(...).collect();
   if records.is_empty() {
       return Ok(0);
   }
   ```

   因此当新包的 `prompts.json` 是空数组，或所有元素都没有有效 `content` 时：
   - designdb 的 `prompts` 文档会被 `set_prompts_doc` 覆盖为空；
   - 但 kv 中该插件 `{plugin_uuid}:prompt:` 前缀下的旧记录不会被删除，继续可被检索。

2. `kv_collection(plugins_type)` 只根据**新包**的 `plugins_type` 选择集合。如果插件从
   `chat_think` 改成 `chat_reply`（或从 chat 类型改成非 chat 类型），旧集合
   （`chat_think`）中该插件的记录不会被清理，形成跨类型残留。

3. 当某条提示词的 `content` 未变化时，代码跳过该条记录：

   ```rust
   if old_map.get(key).map(String::as_str) == Some(content.as_str()) {
       continue;
   }
   ```

   因此以下变化不会同步到 kv：
   - 提示词顺序变化（`rank` 不变）；
   - 插件改名（`meta.plugin_name` 不变）；
   - `id` / `name` 变化但内容相同（key 可能变化，旧 key 会被当作 stale 删除，新 key 写入；
     但仅改名且 key 仍相同的情况不会更新 meta）。

## 影响

- 删除或清空提示词后，旧内容仍可能被 kv 检索到；
- 修改提示词顺序后，召回排序与 `prompts.json` 不一致；
- 插件改名后，kv 元数据仍是旧名称；
- 类型切换后，同一插件可能在多个集合中都有记录，行为不确定。

## 处理方案（已实施）

1. `sync_prompts_kv` 在 `prompts` 为空时也会读取并删除目标集合中该插件前缀下的记录，
   与 designdb 的“整体覆盖为空”保持一致。
2. `installed_plugin` / `find_installed` 额外读取旧 `plugins_type`；`sync_prompts_kv`
   在类型变化时扫描已知集合（排除新集合）并清理该插件的记录；旧类型为空或未知时同样扫描。
   新包没有 `prompts.json` 但类型变化时，用 designdb 中已有提示词迁移到新集合。
3. `kv::list_records` 返回 `KvRecord`（key / value / rank / meta），同步时比较三者：
   - 内容变化：写入并重新向量化；
   - 仅 rank / meta 变化：更新记录，不重新向量化（`force: false`，
     依赖 kv_lib 的 `text_hash` 判断）。
4. 新增 `kv::collection_exists`，先确认集合存在，避免对不存在的旧集合执行 list/delete。
5. 文档同步：`docs/data-model.md`、`docs/plugin-package.md`、`skills/install.md`、
   `skills/update.md`。
6. 新增 3 个单元测试；`cargo test` 通过（13 个）。

## 已确认

- kv_lib 的 `put_one` 在 `force = false` 且 `text_hash` 未变时只更新 value / meta / rank，
  不重新嵌入；内容变化会因 `text_hash` 变化重新嵌入。
- 旧集合清理按 `{plugin_uuid}:prompt:` 前缀删除，不会影响其他插件。
- 空数组清理与 designdb 的整体覆盖语义一致。

## 未处理 / 后续

- `delete_plugins` 仍不清理该插件的 designdb 提示词与 kv 记录；删除后重新安装会通过
  “旧类型为空扫描已知集合”清理残留。若需要删除即清理，建议另开 issue。
- `KV_COLLECTIONS` 与 `kv_collection` 的映射需要同时维护；新增 kv 集合时要同步更新。

## 复现思路

1. 安装一个 `plugins_type: chat_think` 且包含提示词的包，确认 kv `chat_think` 有记录；
2. 将 `prompts.json` 改为 `[]`，执行 `update_plugin`，检查 kv 旧记录是否仍在；
3. 将 `plugins_type` 改为 `chat_reply`，再次更新，检查 `chat_think` 中是否仍有旧记录；
4. 调整 `prompts.json` 中两条提示词的顺序，检查 kv 的 `rank` 是否变化。

修复后预期：空数组清理旧记录；类型切换后旧集合不再有该插件记录；
仅顺序变化时 `rank` 更新，内容未变不会重新向量化。
